# Adopting a recorded Playwright test into your repo

For Cursor, Copilot, any other coding agent, or a human working by hand.

## The procedure

**The full procedure lives in [`.claude/skills/adopt-recorded-test/SKILL.md`](.claude/skills/adopt-recorded-test/SKILL.md).
Read that file and follow it.** Ignore its YAML frontmatter — that is only there so Claude Code can
auto-invoke it; the body is plain markdown and applies to any agent.

It is kept as one file on purpose: a second copy of the same instructions would drift out of sync, and
you'd have no way to tell which one was current.

Prompt to use:

> Read `adoption-kit/.claude/skills/adopt-recorded-test/SKILL.md` and follow its procedure to adopt
> this recorded test into our suite: `<paste the script, or give a path>`

## What you're dealing with, in short

A recorded test is a **reference**, not a finished test. It is generated by watching someone click
through an app, so it:

- hardcodes absolute URLs, pinning it to one environment
- inlines every locator, with no page objects
- names its data positionally (`data.step7`, `data.step8`)
- leaves its assertions **commented out** — so it passes while proving nothing
- carries artifacts of a human typing: the same field filled three times in a row, a click on a field
  immediately before filling it, the same navigation recorded twice
- has a placeholder title like `'TODO rename: button Create'`
- brings **no authentication**, and needs none — your suite already has a mechanism

## The six phases

| | |
| --- | --- |
| **1. Discover** | Read the rules files, the Playwright config, the tsconfig paths, the lint config — then read the 2–3 existing specs nearest the feature. **Conventions in code beat conventions in docs.** Produce an explicit convention profile before writing anything. |
| **2. Translate** | Map fixtures, page objects, locators, URLs, data, titles, and assertions onto that profile. Search for an existing locator before adding one. Reuse before you create. |
| **3. Prune** | Collapse duplicate consecutive fills to the final value; drop a click that precedes a fill of the same input; collapse a navigating click followed by a `goto` to the same place. **But never prune a step that might trigger behaviour** — blur validation, lazy loads, debounced search. When unsure, keep it and flag it. |
| **4. Assert** | The recorder cannot know intent. Add an assertion that reflects the *purpose* of the flow — for a create flow, that the thing now exists, not that a toast appeared. |
| **5. Verify** | Typecheck, lint, run it, **run it twice** (that's how you find missing unique-name suffixes), and deliberately break it to confirm it fails informatively. |
| **6. Report** | What you applied, reused, added, and pruned — item by item — plus what still needs a human decision. Assertions head that list. |

## Two rules that override everything

1. **Discover the repo's conventions; never assume them.** Nothing in this kit describes your repo,
   because it doesn't know your repo.
2. **Never add a login step.** The recording has no auth and needs none. Find how this repo
   authenticates its tests and use that. Do not import anything from the recorder's own harness.
